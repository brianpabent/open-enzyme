# Independent comp review — comp-011

## Bottom-line verdict
Action required — the core sequence-level conclusion (“*C. utilis* P78609 is a MODERATE cassette-design risk vs *A. flavus* LOW”) is broadly plausible as a mechanistic-extrapolation prior, but the artifact-summary contract is not clean. The committed outputs still contain stale hardcoded numbers and classifications, the intended ALLN-346-mutated construct is recommended but not actually analyzed, and several load-bearing claims rely on unverified citation strings or proxy substitutions.

## Implementation and constraint closure

I traced the executable pipeline from FASTA/JSON inputs through `analyze.py` into `outputs/cassette_analysis.json` and `outputs/summary.md`.

**What the computation actually does**
- Loads P78609 uricase and P02788 lactoferrin FASTA.
- Performs amino-acid-level codon-compatibility proxy analysis using hardcoded origin-organism preferred codons and the `a_oryzae_codon_usage.json` RSCU table.
- Scans mature payload sequences for internal `KR` KEX2 sites and classifies by P1′ residue.
- Scans routing motifs: ER-retention, PTS1/PTS2.
- Counts cysteines and applies a manually supplied known-disulfide count.
- Scans `N-X-S/T` sequons.
- Synthesizes a combined “dual-cassette burden” verdict.

**Major model-fit limitations**
- The computation resolves a **sequence-level cassette-risk question**, not the full question of whether the Ward architecture “handles” the payload physiologically. It does not model urate, oxygen, H₂O₂, product formation, residence time, transport, or gut-lumen substrate access. Recent wiki text correctly defers topology and physiology to §1.33, but the README/question still partially inherits the older “Ward architecture out of the box” framing.
- The analyzed uricase is **wild-type P78609**, while the recommendation repeatedly says to use **P78609 + ALLN-346 mutations**. This is not a minor distinction: the disclosed ALLN-346 mutation **I132R** is immediately at the P1′ residue of the position-130 `KR` site (`KRI` → `KRR`), likely changing the KEX2 scoring for that site if a fusion topology is later selected. The artifact should analyze WT and intended mutant sequences separately, or stop recommending the mutant construct as if it had been cassette-checked.
- “Codon burden” is an **amino-acid/proxy-origin-preferred-codon calculation**, not actual CDS analysis and not vendor codon optimization output. The HEAVY *C. utilis* conclusion is plausible, but the exact CAI proxy is not a measured property of the actual construct.
- “Disulfide load” is a **bulk-count comparator**, not an ER-folding capacity model. The artifact now labels this better than before, but any claim that lactoferrin is “equal to Huynh” is only equal by bulk count, not architecture.

**Stored-but-unused or inconsistently used inputs**
- `glucoamylase_carrier.fasta` is present but not used. The code analyzes payload internal sites, not the actual glucoamylase carrier/fusion junction, carrier KEX2 sites, or junction geometry.
- Several `kex2_site_specs.json` fields are documentation-only or unused in executable logic: `huynh_2020_validated_linker`, `alternative_linkers`, `internal_kr_site_risk.risk_categories`, `p1_prime_modifier`.
- `a_oryzae_codon_usage.json` includes `freq_threshold`, `rare_codons_list`, and a `logic` statement, but the code uses only `rscu_threshold` and implements `rscu < 0.4`. This conflicts with the input’s documented rare-codon logic/list and helps produce the “0 rare codons” result. The overall HEAVY verdict is driven by CAI proxy, so the top-line risk probably survives, but the rare-codon count/hotspot fields are not semantically closed.
- Lactoferrin codon burden is labeled `LOW` by code, but prose says full codon optimization is required in practice. That may be true engineering practice, but it is not derived by the implemented codon-burden rule.

**Concrete implementation/output defects**
- `outputs/summary.md` still says in the comp-011 vs Huynh table: **“Total disulfides | 17 (all on Lf)”**. The corrected JSON and most other summary sections say 16. This is a hardcoded stale number in `write_summary`.
- `outputs/cassette_analysis.json` under `combined_burden.c_utilis_vs_aflavus_material_differences` says **“positions 130 HIGH + 138 MODERATE”**, while the actual KEX2 result and summary tables classify both 130 and 138 as HIGH.
- The README reproduction command says `cd experiments/comp-011-c-utilis-uricase-cassette-compatibility`; the tracked path is `wiki/etc/experiments/comp-011-c-utilis-uricase-cassette-compatibility`. Unless an unlisted symlink exists, the command is wrong.
- `outputs/summary.md` cross-reference links use paths such as `../../wiki/...` from inside `wiki/etc/experiments/.../outputs/`, which do not resolve to the top-level `wiki/` directory.

**Constraint closure**
- **Uricase reaction substrates/products:** Uricase consumes urate + O₂ and generates peroxide through the urate-oxidation/product-decomposition pathway. This artifact does not model substrate concentration, O₂ limitation, H₂O₂ burden, allantoin/5-HIU fate, transport, or finite exposure time. This is acceptable only if the comp is explicitly scoped as cassette-sequence analysis and not physiological efficacy.
- **Lactoferrin function:** Iron binding, glycosylation occupancy, and solid-state folding are not modeled. The artifact cites Ward 1995 and Huynh 2020 as precedents but does not verify them directly.
- **Localization:** The TKL PTS1-like motif is flagged. The assertion that an N-terminal amyB signal peptide outcompetes the C-terminal PTS1 is a plausible design assumption, not implemented or proven.
- **Free cysteines:** The 4 free cysteines are correctly surfaced as a theoretical ER aggregation/PDI-engagement risk, but no accessibility, redox, or aggregation model is implemented.
- **Sensitivity:** There is no parameter sweep over the dominant uncertainties: *C. utilis* codon-table uncertainty, KEX2 P1′ species specificity, structural accessibility, free-Cys surface exposure, glycosylation occupancy, or actual ALLN-mutant sequence effects.

## New connections or implications

1. **ALLN-346 I132R is not just “adjacent” to the KR site; it likely changes the KEX2 P1′ classification of the position-130 WT site if a fusion topology is chosen.** WT P78609 has `KRIT` at 130–133; I132R would make the P1′ residue basic. Under this artifact’s own KEX2 rules, that likely shifts the site from HIGH to reduced-efficiency/MODERATE. The intended mutant cassette therefore needs its own KEX2 scan.

2. **The *C. utilis* free-Cys issue is a chaperone-orthogonality issue, not only a QC-band issue.** The artifact notes SDS-PAGE monitoring, but the broader implication is that *C. utilis* uricase may partially collapse the “uricase = PDI-orthogonal” assumption used for *A. flavus*. `chaperone-orthogonal-stacking.md` already captures this directionally; §1.33/§1.9B should measure whether it manifests as lower product, aggregation, or viability/UPR stress.

3. **A topology matrix can reverse which sequence features matter.** In direct secretion, the two internal KR sites are informational; in a fusion topology, they become design-changing; in an intracellular/peroxisomal topology, the TKL signal and peroxide/catalase localization may be more relevant than KEX2. Comp-011’s results should be treated as topology-conditional annotations, not a general clearance of P78609.

4. **The lactoferrin codon result illustrates a proxy-practice split.** The code calls human lactoferrin codon burden LOW by amino-acid preferred-codon proxy, while the engineering text still says codon optimization is required in practice. This should be generalized as a warning: the CAI proxy is useful for variant deltas, not a replacement for construct-level CDS design.
