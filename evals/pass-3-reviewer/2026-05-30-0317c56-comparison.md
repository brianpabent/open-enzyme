# Pass 3 reviewer eval — DeepSeek V4-Pro vs. GPT-5.5

Candidate: **`deepseek/deepseek-v4-pro`** with a DeepSeek-tuned Pass 3 prompt
(`scripts/sweep-prompt-3-review-deepseek.md`), against the 2026-05-30 sweep
(`0317c56`, 22 items). Ground truth: the GPT-5.5 reviews that actually shipped
this sweep (the `> **Claude review — …**` blockquotes now in
`synthesis/done/2026-05-30-*.md` + `synthesis/queue/2026-05-30-*.md`).

Plan: `evals/pass-3-reviewer/2026-06-01-deepseek-candidate-plan.md`.
Methodology + grading axes: `evals/pass-3-reviewer/README.md`.

## TL;DR

DeepSeek V4-Pro is **~10–25× cheaper**, **format-compliant on content** (one
cosmetic preamble-line defect, see below), verifies **harder** (read the
load-bearing source 4× chasing the §1.25 cost), and — most important — **uses
the route-to-verification pattern GPT-5.5 never reached for** (3 `[VERIFY:
lit-scan]` flags + 1 explicit `Defer.` vs. GPT-5.5's 0 of either). On
**catch-test 1 (theaflavins × ABCG2)** DeepSeek passes where GPT-5.5 failed:
it routes the unverifiable ABCG2 world-claim to a lit-scan instead of rejecting
on corpus-absence. On **catch-test 2 (§1.25 stale cost)** both models miss the
same way (assert the stale table value as truth), but DeepSeek at least
*attempted* the cross-location check Rule 3 asks for — it just executed it
wrong. Net recommendation: **adopt DeepSeek for Pass 3, but keep a periodic
GPT-5.5 cross-check** to preserve cross-vendor heterogeneity (DeepSeek already
owns Pass 1) — and **fix catch-test 2 at the source**, not in the prompt.

## Grading

### Cost (objective)

DeepSeek V4-Pro live OpenRouter pricing: **$0.435 / $0.870 per Mtok** (in/out),
cache-read **$0.0036 per Mtok**. GPT-5.5: **$5.00 / $30.00 per Mtok**,
cache-read $0.50.

| | Run B tokens | Cost (cache-aware) | Cost (no-cache naive) |
|---|---|---|---|
| **DeepSeek V4-Pro** | in 5,889,630 (93% cached) / out 19,941 | **$0.218** | $2.58 |
| **GPT-5.5** (est., same input profile) | ~same in / out | **~$5–8** | ~$30+ |

The per-Mtok ratio is the robust number: DeepSeek input is **~11.5× cheaper**,
output **~34× cheaper**, cache-read **~140× cheaper**. On the cache-heavy Pass 3
workload (93% input cache hit here), realized savings are **~25–35× per sweep**.
Pass 3 runs every sweep; this compounds.

### Tool iterations / research depth (objective)

- **Run B: 14 iterations** (self-terminated before the 16 cap), ~30 tool calls.
  Read `validation-experiments.md` **4 separate times** chasing the §1.25 cost —
  exactly the multi-axis behavior Rule 3 asks for (even though it landed wrong;
  see catch-test 2).
- **Run A: hit the full 16-iteration cap** (~41 calls), re-reading
  `validation-experiments.md` and `theaflavins.md` repeatedly.
- This is **high** verification intensity — the opposite of the BioDesignBench
  "~14% of expert intensity, never discard a candidate" failure mode. DeepSeek
  did not treat the first grep as deterministic truth; it kept probing.

### Cache hit rate (objective)

93% input cache hit (Run B), 82% (Run A). Healthy; the warm-cache prefix is
being reused across iterations as designed.

### Format compliance

- **Content blockquotes: PASS** — exactly 22 `> **Pass 3 review —` openers, 21
  `<<<NEXT>>>` separators, correct verdict/OVERLAP/GAP vocabulary throughout,
  GAP tags only on disagreement verdicts.
- **One cosmetic defect:** Run B leaked a single preamble line before the first
  blockquote: `Now I have enough information to write the 22 reviews. Let me
  proceed:`. The merge script (`synthesis-emit-files.py`) counts `<<<NEXT>>>`
  separators and **bails / corrupts the first per-item file** on stray leading
  text, so this would break a production run as-is. Run A did **not** leak
  preamble. This is a known DeepSeek tendency (thinking-out-loud before the
  deliverable). **Mitigation:** the driver already appends a forcing-final user
  turn ("Begin your response with `> **Pass 3 review —`") only when
  `forcing_final`; Run B self-terminated *before* the cap so that turn never
  fired. Options: (a) strip any pre-first-blockquote text in the emitter
  (cheap, robust, recommended), or (b) tighten the prompt's anti-preamble rule
  further. Not a blocker, but must be fixed before production.

## Catch-tests (the gold)

### Catch-test 1 — theaflavins × ABCG2 (connection-1). DeepSeek: **PASS.** GPT-5.5: **FAIL.**

The synthesizer claimed theaflavins are functional ABCG2 inhibitors "sharing the
tannin-class profile." This is a **world-claim** the historical corpus can
neither confirm nor refute.

- **GPT-5.5 (shipped):** `Push back. [OVERLAP: EXTENSION] [GAP: tool-gap]` — basis
  was *corpus-absence only* (`theaflavins.md` "No ABCG2 interaction documented";
  `abcg2-modulators.md` lists EGCG/quercetin/curcumin/genistein, not theaflavins).
  Recommended adding an open question. This is the exact laundering failure: it
  treated "not in our corpus" as "the synthesizer is wrong." (Ground truth: the
  claim was *inverted* — theaflavins up-regulate ABCG2 in vivo, Tai 2020 — which
  no reviewer without lit-scan tools could know, but the *right* move was to route
  to the scan.)
- **DeepSeek (Run B, historical state):** `Partial. [OVERLAP: EXTENSION] [GAP:
  both]` — confirmed the NLRP3-orthogonality half as corpus-supported, then on
  the ABCG2 half wrote, verbatim: *"Per Rule 2, this is a world-claim routed to
  `[VERIFY: lit-scan]` — theaflavin × ABCG2/BCRP functional modulation,"* and
  split the action into (a) ship the NLRP3 cross-reference vs. (b) defer the
  ABCG2 claim to lit-scan before any supplements-stack entry. **This is the
  correct behavior** — route-to-verification, not reject-on-absence.
- **Scoring nit:** DeepSeek used `Partial.` + `[GAP: both]` rather than a clean
  `Defer.` Since the operative move was deferring the ABCG2 sub-claim to a scan,
  a pure `Defer.` (no GAP tag) would have been cleaner. But it correctly
  half-confirmed the orthogonality and correctly routed the ABCG2 half — the
  catch-test (does it route-to-verify vs. reject-on-absence?) is **passed**. The
  Rule-2 reasoning was invoked by name.

### Catch-test 2 — §1.25 stale cost (experiment-3). DeepSeek: **MISS (same direction as GPT-5.5).** Partial credit for attempting the cross-check.

At the sweep commit, `validation-experiments.md` had a genuine **header-vs-table
inconsistency**: the summary table (line 60) read `$3,500–5,500`; the detailed
§1.25 header (line 996) read `$4,445–6,745 (… re-scoped 2026-05-16; … updated
2026-05-17)`. The synthesizer quoted the *header* (`$4,445–6,745` — the correct,
current value).

- **GPT-5.5 (shipped):** `Push back. [OVERLAP: RESTATEMENT] [GAP: tool-gap]` —
  asserted `$3,500–5,500` as the real number and called the synthesizer's
  `$4,445–6,745` wrong. Cited the first corpus location (the stale table) as
  ground truth; never noticed the two locations disagree.
- **DeepSeek (Run B):** `Push back. [OVERLAP: EXTENSION] [GAP: tool-gap]` —
  **same wrong direction.** It wrote *"Per Rule 3, I checked both the queue
  summary table and the detailed §1.25 section header; only the queue table was
  grep-able,"* concluded the synthesizer's number was stale, and recommended
  reverting to `$3,500–5,500`.
- **Assessment:** DeepSeek **engaged Rule 3** (it explicitly went looking for two
  locations — GPT-5.5 didn't even try) but **executed it wrong**: it read
  `validation-experiments.md` four times yet claimed "only the queue table was
  grep-able," when the §1.25 header (lines 996 + 1042) was present and even
  *self-labels itself* as the re-scoped/updated value — the exact tell it should
  have used. So the behavioral disposition is better (cross-check attempted), but
  the outcome is the same miss.
- **Root-cause read:** this catch-test is **partly unfair to any reviewer.** The
  corpus shipped a real internal contradiction with the stale value sitting in
  the *summary table* (the surface a reviewer reasonably treats as authoritative)
  and the correct value buried in the detail header. The durable fix is **at the
  source** — the table has since been reconciled — plus a prompt nudge: "summary
  tables can lag re-scoped detail headers; when a cost/number appears in both,
  prefer the one self-labeled 're-scoped/updated' and flag the inconsistency."
  Neither prompt's Rule 3 was concrete enough to force the right tiebreak. The
  DeepSeek prompt's Rule 3 already names the header-vs-table trap and says "flag
  the inconsistency"; it did not say "the *re-scoped/updated*-labeled location
  wins the tiebreak." Consider adding that.

## Heterogeneity tradeoff (the call to make explicitly, not by default)

DeepSeek is **already the Pass 1 (propagate) model.** Moving Pass 3 to DeepSeek
means one vendor does both propagation and review, and GPT-5.5 — the only OpenAI
presence in the pipeline — drops out entirely. The multi-model heterogeneity
guard (`wiki/etc/open-source-platform.md` §"Multi-model synthesis as guard
against epistemic homogenization") weakens: a DeepSeek-shared blind spot could
survive both Pass 1 and Pass 3 unchallenged. Pass 2 is Grok 4.20, so the
pipeline would still be DeepSeek → Grok → DeepSeek — two vendors, not three, with
the same vendor bookending.

This eval gives a **strong cost + catch-rate signal** for DeepSeek (catch-test 1
is a clean win on the exact failure family that motivated the eval; cost is
~25–35× lower), but the heterogeneity cost is real. Recommended posture:

1. **Adopt DeepSeek V4-Pro as the default Pass 3 reviewer.** Cost + catch-test 1
   justify it. Fix the preamble-leak defect first (emitter strip is cheapest).
2. **Keep GPT-5.5 (or another OpenAI/3rd-vendor model) as a periodic Pass-3
   cross-check** — e.g. every Nth sweep, or on high-stakes sweeps (new H-card,
   canonical-page change). This preserves cross-vendor coverage without paying
   GPT-5.5 every sweep. Cheapest way to keep the guard alive.
3. **If full replacement is chosen instead**, move **Pass 1 to a different vendor**
   (e.g. Qwen or Gemini) so propagation and review aren't both DeepSeek — that
   restores the bookend heterogeneity the guard depends on.
4. **Add `deepseek/deepseek-v4-pro` to the script pricing dicts** so cost prints
   correctly in CI, and consider adding the "re-scoped-label wins" tiebreak to
   Rule 3 of all three Pass-3 prompts (the catch-test-2 root cause is
   prompt-shared, not DeepSeek-specific).

Do **not** let GPT-5.5 drop out by default — make the heterogeneity call
explicitly. Recommendation: **option 1 + 2** (DeepSeek default, GPT-5.5 periodic
cross-check).
